1 Why the current design looks flat

Four specific technical decisions in the current code create the flat, illustration-like appearance.

Area Current (V3) Required (V5)
Material model MeshLambertMaterial — Lambertian diffuse only, no specular, no PBR. All surfaces look identically matte regardless of material type. MeshStandardMaterial / MeshPhysicalMaterial — metalness, roughness, normalMap, aoMap, emissive. Concrete looks like concrete. Track reads as rubberised.
Shadow mapping shadowMap not enabled on the renderer. No object casts or receives shadows. Everything floats. renderer.shadowMap.enabled + PCFSoftShadowMap. Grandstands cast long golden-hour shadows across the track.
Stadium geometry ShapeGeometry flat rings extruded from 2D paths. Seating is a single-piece flat disc per tier. No structural depth. Stepped BoxGeometry rows (each row is a raised horizontal slab), curved in the XZ plane via instancing or custom BufferGeometry. Produces real architectural depth.
Lighting rig 1× AmbientLight + 1–2 DirectionalLights, no tone mapping, linear colour space. HemisphereLight (sky/ground) + warm DirectionalLight (sun, castShadow) + fill + 6× PointLight floodlights (emissive halos). ACESFilmicToneMapping. sRGB output encoding.
Character geometry CylinderGeometry torso, SphereGeometry head, flat-colour materials. No face detail, no joints, no clothing structure. Lathe/TubeGeometry head with bevelled contours, separate eyelid/iris/pupil meshes, hair cluster of extruded shapes, jersey with collar and seam ridges, shoe with distinct sole plate.

2 Achievable vs. requiring external tools

A clear-eyed split between what can be built in code and what needs Blender or an asset library.

Achievable in code

  • PBR materials (roughness, metalness, emissive)
  • Shadow mapping (PCFSoft)
  • Hemisphere + directional + point lights
  • ACESFilmic tone mapping, sRGB output
  • Properly stepped grandstand tiers (BoxGeometry rows)
  • Horseshoe open-front architecture
  • Detailed track (oval + lane markings + start/finish)
  • Structural columns, roof canopy geometry
  • Dense instanced spectators with colour variation
  • Significantly improved chibi proportions (lathe heads, hair clusters, joint geometry)
  • Team jerseys with collar, cuffs, bib detail
  • 4 physique silhouettes via parameterised scaling
  • Smooth running animation (sinusoidal joint rotation)
  • Collapsible Sprint Board panel
  • 3-level camera system with smooth transitions
  • Contact shadows (THREE.ContactShadows or DecalGeometry)

Needs external assets

  • Photorealistic hair strand simulation
  • Cloth simulation / fabric fold realism
  • Blendshape facial expressions
  • Mocap-quality skeletal running cycles
  • High-poly sculpted hands with individual finger bones
  • Sub-surface skin scattering
  • Pre-baked ambient occlusion textures
  • Normal-mapped abs (requires a texture file)
  • Lip sync / facial phonemes
Recommendation: Use Mixamo (free, rigged GLB characters + animations) for the character base. Apply team-colour vertex paint and chibi head scaling at load time via Three.js. This gives skeletal running, jump and throw animations with zero modelling effort.

3 Character asset strategy

Two approaches with honest tradeoffs.

Option A — Recommended

Mixamo GLB + Three.js GLTFLoader + head-swap chibi rig

Download a Mixamo character (free, no attribution required for personal/commercial use). Export as GLB with skeleton. Load via THREE.GLTFLoader. At runtime: scale the head bone 1.6×, adjust torso taper per physique, apply team colour to jersey via vertex shader. Use Mixamo's "Running", "Sprint", "Throw", "Jump" animation clips — these are mocap-quality skeletal animations that already meet the reference standard.

Quality ceiling: Matches or exceeds the uploaded marathon runner reference. Hair will be modelled, clothes will have folds. Physique changes via morph targets if you export a few variants, or via bone scaling at runtime.

Limitation: Requires downloading the GLB file from mixamo.com manually (no API), committing it to the repo, and loading via GLTFLoader. File size ~2–5 MB per character variant. This is entirely feasible.

Option B — Fallback

Highly improved procedural geometry (no external files)

Replace CylinderGeometry with LatheGeometry heads (smooth curved profile), add layered eyelid/iris/pupil geometry, hair cluster of custom ExtrudeGeometry shapes, jersey with separate collar and cuff meshes, oversized shoe with distinct sole. MeshStandardMaterial with roughness variation per body part.

Quality ceiling: Substantially better than current. Will look like a polished stylised 3D character — not matching the Blender-sculpted reference image exactly, but clearly a premium geometric character rather than a placeholder. Comparable to indie 3D game assets.

Limitation: No true skeletal animation. Running is achieved by sinusoidal joint group rotation. Hair will always be blocky. Hands will not have individual fingers.

My recommendation: proceed with Option B for the Stage 2 preview so you can evaluate the quality in a live Three.js scene today. Simultaneously, download one Mixamo character GLB and I will integrate it in Stage 3 — that is the path to matching the reference image exactly.
